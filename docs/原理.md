# 原理与排查记录

## 背景

macOS 26（Tahoe）移除了自 10.7 Lion 起就存在的 Launchpad，换成了与 Spotlight 深度绑定的
「应用」（`Apps.app`）——按字母排序、不能自由布局、不能建文件夹。

## 核心结论

**启动台的界面代码在 `Dock` 里，不在 `Launchpad.app` 里。**

### 证据 1：两个 app 都是空壳

| 文件 | 大小 | 行为 |
|---|---|---|
| `/System/Applications/Launchpad.app`（26 Beta） | **99 KB** | 发一条 `com.apple.launchpad.toggle` 就退出 |
| `/System/Applications/Apps.app`（26.7.1） | **98 KB** | 同上 |

99 KB 装不下一个全屏图标网格的实现。它只是**触发器**。

### 证据 2：Dock 里有两层东西

对 `Dock.app/Contents/MacOS/Dock` 做字符串分析，26.0 和 26.7.1 两版**都**包含：

```
LPAppManager / LPAppTree / LPAppSource / LPAppTreeNode / LPDatabaseException
LaunchPadLayout.plist
"Entering Launchpad" / "Exiting Launchpad"
com.apple.dock.launchpad / com.apple.launchpad.toggle
com.apple.launchpad.launcher / com.apple.apps.launcher
```

这些是**数据层**（读数据库、算布局）和**路由逻辑**（按调用方 bundle id 分流）。

### 证据 3：差别在版本

| | macOS 26.0 | macOS 26.7.1 |
|---|---|---|
| `Dock.app` 版本 | **2419** | **2427.6** |
| `DTSDKName` | `macosx26.0.internal` | `macosx26.7.internal` |
| 老启动台界面类 | ✅ 有 | ✅ 仍有，入口固定走新版 |
| `LP*` 数据层符号 | 51 个 | 51 个（**完全相同**） |

两版的 `LP*` 符号、依赖（各 78 个）完全一致。进一步检查 Objective-C
元数据发现，2427.6 仍有 `Springboard`、`ECSBPage`、`ECSBGroupLayer`
和 `ECScrollableGridLayer` 等界面类。两版 `Springboard` 都有 159 个实例方法。
区别是 2419 的 `showForReason:` 根据 `SpotlightUI/SpotlightPlus` 特性开关
决定显示路径，而 2427.6 的对应判断直接返回真，固定转到新版“应用”。
此外 2427.6 启动时不再构造旧界面的 `LPSpringboard` 实例。只改
FeatureFlag 或分流字节都不能恢复旧界面；第一版分流补丁重启后
Dock 正常，但启动台未显示。第二版补回实例创建后已能显示原生启动台；
第九版的软件位图后端进一步通过了本机用户的分辨率切换验证，完整包见 v1.4 预发布。

## 走不通的方案（都实测过）

### 1. 只放 `Launchpad.app`

进程启动即退（`exit 0`，无输出），Dock 无任何反应。
原因：它是触发器，默认 26.7.1 Dock 仍固定转向新版路径，也未创建旧启动台实例。

### 2. 改 bundle id

把 26.7.1 的 `Apps.app` 复制一份、改 `CFBundleIdentifier` 为
`com.apple.launchpad.launcher`，期望 Dock 按 id 分流走老路径。**无效**——
改 bundle id 并不能恢复旧界面的固定入口判断和实例创建；UI 类本身仍保留在二进制中。

### 3. 改 Dock 偏好

```bash
defaults write com.apple.dock showSpotlightBasedLaunchpad -bool false
```

Dock 里有 `_showSpotlightBasedLaunchpad` 这个 ivar，但**没有任何代码读这个偏好键**。
`lsof -p <Dock pid>` 验证：重启后 Dock 没有打开任何 launchpad 相关文件，
`~/Library/Application Support/Dock/` 始终不存在。

### 4. 只写 `SpotlightPlus` FeatureFlag

26 Beta 的 `Launchpad.app` 声明了：

```xml
<key>LSRequiredFeatureFlags</key>
<dict><key>SpotlightUI/SpotlightPlus</key><true/></dict>
```

写入 `/Library/Preferences/FeatureFlags/Domain/SpotlightUI.plist` 设 `SpotlightPlus=false`
后重启 Dock —— **界面无变化**。

原因：这个 flag 只对**声明了 `LSRequiredFeatureFlags` 的 app** 生效。
26.7.1 的 `Apps.app` 根本没声明它，开关没有作用对象。

### 5. 整套替换 Dock + Spotlight + Apps

社区工具 [SimpleLaunchPadRestore](https://github.com/laobamac/SimpleLaunchPadRestore) 的做法，
但它：

- 自带的 `Dock.app` 是 2025-08 的 26 Beta
- 明确提示代价是**聚焦功能失效**
- 已于 2026-06 停止维护

**实测证明只换 Dock 就够**，不必付聚焦失效的代价。

## 为什么必须重建系统快照

macOS 11 起，系统卷是**只读快照**（sealed snapshot）。直接写 `/System` 会失败或无效。

正确做法：

```bash
# 1. 把系统卷以可写方式挂到别处（不影响正在运行的快照）
mount -o nobrowse -t apfs /dev/diskXsY /System/Volumes/Update/mnt1

# 2. 在挂载点上替换文件
ditto NewDock.app /System/Volumes/Update/mnt1/System/Library/CoreServices/Dock.app

# 3. 重建快照（关键，不做则不生效）
bless --mount /System/Volumes/Update/mnt1 --bootefi --create-snapshot

# 4. 卸载
umount /System/Volumes/Update/mnt1
```

`diskXsY` 必须动态获取（`disk` 编号重启会变）：

```bash
DEV="$(diskutil info -plist / | plutil -extract DeviceIdentifier raw -)"
[[ "$DEV" =~ ^(disk[0-9]+s[0-9]+)s[0-9]+$ ]] && ROOTDEV="${BASH_REMATCH[1]}" || ROOTDEV="$DEV"
```

## 打包成 pkg 时踩的两个坑

### 坑 1：payload 不能写系统宗卷

如果把 `Dock.app` 放进 pkg 的 payload 并装到 `/usr/local/share/`，Installer 会直接失败：

```
The install failed. 软件包正尝试将内容安装到系统宗卷。
```

而且 **postinstall 根本不会执行**。

解法：payload 只放数据卷里的占位文件（`/Library/Application Support/...`），
把 `Dock.app` 放进 **Scripts 目录**，postinstall 用 `$(dirname "$0")` 读同目录。

### 坑 2：不能把「原版备份」打进包

第一版把开发机的 `Dock.app` 备份打包进去当「原版」。拿到别的机器上还原时，
会塞进一个**和对方系统不匹配的版本**，可能直接搞崩对方的 Dock。

解法：postinstall 在安装时用 `ditto` 备份**目标机器当前**的 `Dock.app`。
这样每台机器还原的都是它自己的原版。
