# 完整原生启动台安装包

包版本为 `2427.6.12`，支持 Intel `x86_64` 的 macOS 26.0 及以上（系统 Dock 须为 `2427.6`）；Dock 本身继续使用第九版补丁 `2427.6.9`。历史 v1.5 包为 `2427.6.11`（只认 26.7.1 / 26.7.2），v1.4 包为 `2427.6.10`（只支持 26.7.1 / 25G241）。

## 兼容目标与验证范围

| macOS | Build | 架构 | 包内版本 |
|---|---|---|---|
| 26.7.1 | `25G241` | Intel / `x86_64` | 与 v1.4 包中的 Dock payload 逐文件相同 |
| 26.7.2 | `25G332` | Intel / `x86_64` | 独立构建的完整 Dock 2427.6 |
| 26.7.3 | `25G342` | Intel / `x86_64` | 与 25G332 逐字节相同，共用同一份候选 Dock |
| 其他 26.x | 任意 | Intel / `x86_64` | 回退到 `FallbackVariant`（当前为 `25G332`） |

安装器先按 build 精确匹配变体；没有对应变体时读取清单的 `MinimumProductVersion`（26.0）与 `FallbackVariant`，
用回退变体的候选 Dock，并在安装前用 Apple 签名确认本机 Dock 仍为原版。无论精确匹配还是回退，
备份都写到 `Originals/<本机 build>/`，卸载只还原本机 build 的备份。Apple Silicon 仍不在支持范围内。
系统 Dock 不是 `2427.6` 时（例如更早的 26.x 仍带 2419）安装器会中止，不会降级系统 Dock。

26.7.1 payload 取自已发布的 2427.6.10 安装包，并已确认与旧包逐文件一致。26.7.2 的入口调用 ABI 已做静态核对；新候选和辅助工具的签名检查、完整 bundle 文件库存检查以及打包构建检查均已通过。**26.7.2 已于 2026-10-27 在本机安装并重启加载补丁；启动台打开、动画和分辨率切换等功能仍待实测确认。**

目标系统仍需关闭 Authenticated Root，并具备运行重新签名系统程序的条件。本包不会更改 SIP、Authenticated Root、AMFI、EFI 或驱动设置。“不要求预装 OCLP”表示包自带完整 Dock 和资源，不表示普通 Mac 的默认安全设置允许替换系统 Dock。

## 安装、升级与还原

Install 包自带两套完整 `Dock.app`、偏好设置助手、备份和 bundle 校验工具。目标电脑不需要事先安装旧启动台、OCLP 或本项目，也不需要构建电脑上的 `Dock.app.orig`。

首次安装会备份目标电脑当前 Dock，并按 build 保存：

```text
/Library/Application Support/LaunchpadRestore/Originals/25G241/Dock.app.orig
/Library/Application Support/LaunchpadRestore/Originals/25G241/Dock.app.orig.manifest.plist
/Library/Application Support/LaunchpadRestore/Originals/25G332/Dock.app.orig
/Library/Application Support/LaunchpadRestore/Originals/25G332/Dock.app.orig.manifest.plist
```

系统版本升级后，新备份会写到新 build 的目录。旧备份会保留；能证明属于当前 build 的旧全局备份才会迁移或使用，其他 build 的备份只保留，不会拿来替代当前系统 Dock。Uninstall 只使用与当前系统 build 匹配、且通过本机硬件、APFS 卷组和文件库存校验的备份；找不到有效同 build 备份就停止，不会跨 build 还原。

替换或还原前，安装器还会读取实际挂载的可写系统卷 `SystemVersion.plist`，确认它的版本和 build 与当前选择一致，防止改错系统卷。

**OCLP 说明：** 已确认，OCLP 还原 root patch（`--last-sealed-snapshot`）会回退系统快照，使 Dock 回到 Apple 原版，本项目的启动台也会消失。完成 OCLP 操作后，如需继续使用本项目启动台，请重新安装与当前系统 build 匹配的包。

安装或卸载会准备新的系统快照，完成后重启生效；安装器不会自行重启。

## 构建

构建脚本必须在 Intel / `x86_64` 的 macOS 26 上运行（来源 Dock 仍须匹配已知的 2427.6 哈希）：

```sh
./scripts/build-native-entry-pkg.sh
```

默认从当前系统的 `/System/Library/CoreServices/Dock.app` 读取 26.7.2 原版，并从本地 v1.4 包 `pkg/LaunchpadRestore-Native2427-Install-2427.6.10.pkg` 取出 26.7.1 payload。脚本会先校验来源 Dock 的版本、架构、可执行文件与 Info.plist SHA-256、Apple 签名，以及 v1.4 基线安装包的 SHA-256。

也可以显式提供来源：

```sh
./scripts/build-native-entry-pkg.sh \
  --source-26.7.1 /absolute/path/to/26.7.1/Dock.app \
  --source-26.7.2 /absolute/path/to/26.7.2/Dock.app
```

如需使用其他位置的已发布基线包，可用 `--baseline-package /path/to/2427.6.10.pkg`；它与 `--source-26.7.1` 不能同时指定。26.7.2 来源也可用 `--source-26.7.2` 替换默认路径。每个来源都必须是未修改的 Apple Dock 2427.6，并匹配该系统 build 的已知哈希和签名。

脚本只构建，不安装、不修改运行中的 Dock、不创建系统快照，也不重启。

## 包内清单与构建记录

`package-manifest.plist` 使用 `FormatVersion=2`，分别记录 `25G241` 和 `25G332` 对应的产品版本、build、原版来源哈希、候选 Dock 哈希、Info.plist 哈希、补丁版本和相对目录。两个候选 `Dock.app` 分别位于 `variants/25G241/` 与 `variants/25G332/`。`bundle-inventory.plist` 记录每个候选 bundle 的普通文件哈希、符号链接目标和目录；安装包内还带版本选择脚本及签名后的辅助工具。

构建检查确认：26.7.1 payload 沿用 2427.6.10 中的完整 bundle；26.7.2 payload 使用对应系统的原版 Dock 构建，并通过签名与库存检查。构建通过不等于两种系统都完成了安装和重启实测；特别是 26.7.2 的运行兼容性仍待实机验证。
